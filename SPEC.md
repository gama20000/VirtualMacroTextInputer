# Specification

*Portuguese original: [docs/pt/SPEC.md](docs/pt/SPEC.md).*

## Destination

A macro pad application for Windows, **Virtual Macro Text Inputer** (called
Macropad until version 0.4; the Python package is still `macropad`), that turns
configurable keys of the ordinary keyboard, and the buttons of an optional
floating panel, into text actions sent to the application in the foreground.
The original key is suppressed when the macro is active and within the
configured scope.

The project stops when the Windows version has been reviewed, manually
validated on Windows (`docs/MANUAL-CHECKLIST.md`), packaged as an executable and
published to two git remotes (a self-hosted Forgejo and GitHub). A Linux
version is outside this destination, but the architecture must keep allowing
it.

## Problem

People who repeatedly type the same codes and texts (e.g. `3E03305`,
`Z51.11{Enter}`) waste time and make mistakes. A physical or virtual Stream
Deck solves this with buttons; this program uses the keys the keyboard already
has and an on-screen panel, with no extra hardware.

## Users

- One main user, on Windows 10/11, who works mostly in other applications and
  wants the program to stay discreet, in the background.
- Edits macros through the interface or directly in the TOML files.
- Speaks European Portuguese; the interface must also exist in English.

## Required behaviour

### Background and life cycle

- Starts with Windows by default (can be turned off); no desktop shortcut;
  notification-area icon; works with no visible windows.
- Closing the settings or the panel does not quit the application; only
  «Quit» in the icon menu does.
- Icon menu: open settings, show/hide panel, choose the active set,
  suspend/resume, quit.
- Restores the active/suspended state, the active set and the panel visibility
  from the previous session. A single instance (a second launch opens the
  first one's settings).
- Notification-area icons: cyan outline (active) and grey with a red dot
  (suspended). Application logo: key «1» → cursor.

### Keys and triggering

- By default, keys 1–4 on the top row (distinct from the numeric keypad);
  initial example: 1 → `3E03305`. Other keys and combinations are
  configurable; a macro may have no key (panel only).
- Modifiers: by default only the bare key triggers (Ctrl+1, Alt+1, Shift+1 keep
  their normal behaviour); configurable to «ignore».
- Holding the key does not re-trigger; events generated by the application
  never trigger macros; keys in the program's own windows do not trigger.
- Duplicate bindings and conflicts with the suspend hotkey are errors.

### Global suspend

- Configurable hotkey (Shift+Escape by default; configurations with the old
  Ctrl+Alt+P are migrated) that toggles active/suspended, also during a macro
  and during `{Delay}`; immediately cancels pending steps and repetitions.
  Suspended: every key behaves normally.
- State visible in the icon, the panel and the settings; clickable **Active**
  and **Suspended** buttons in the settings and on the panel, with distinct
  styles and visible focus.

### Sets and scope

- Create, edit, duplicate, delete, rename, import and export sets; one active
  set at a time, chosen manually.
- Per-set scope: global or a list of executables; outside the scope keys work
  normally and the panel does not send. Switching windows during an execution
  interrupts the pending steps.

### Text actions and repetitions

- Unicode text with `{Enter}`, `{Tab}` and `{Delay:ms}` (0–600000), executed in
  order; line breaks equal `{Enter}`; malformed commands are errors with their
  position. «Type» mode (Unicode SendInput) or «paste» mode (clipboard).
- Repetitions (1–1000) with an interval; no infinite loops; triggers during an
  execution are ignored; execution does not block the interface.

### Settings interface

- Tabs, in this order: **Macros**, **Panel**, **Scope**, **Preferences**.
- Macros: two areas with titles in the same style, **Active** and **Archive**.
  The Active area uses the panel's look (dimensions, colours, title and key
  positions, spacing, number of columns, empty spaces) and is centred; if it
  does not fit, it can be scrolled without cutting macros.
- Dragging reorganises within each area and moves between Active and Archive
  in both directions. On drop, the item lands at the indicated position, before
  or after the item under the pointer, not at the end. Dropping on an empty
  space swaps the button with the space. The interface updates and saves
  immediately. The key never changes with the position; restoring by dragging
  with the key in use asks for the same confirmation.
- Editor for title, key, text, repetitions and interval; automatic save when
  valid; errors in red (including key conflicts); duplicate content (same
  sequence of text and commands) in yellow, with an explanation.
- «New macro» creates exactly one macro, with no key and empty text. «New
  macro», «Counter» and «Empty space» insert the new item right after the
  selected macro in the Active area (after the last one, with several
  selected); with nothing selected, or with an archived macro selected, at the
  end of the Active area. The new item becomes the selection.
- Empty spaces: can be inserted between buttons to compose the grid. They are
  not macros, do not run, do not go to the Archive and are only visible
  (dashed outline) in the settings; on the real panel they take their cell,
  invisible. The layout is saved.
- Counters: a button that shows a count. A short click (or a tap on its key)
  adds the step (default 1). While it is held (mouse or key), the panel button
  shows the elapsed time as a line that runs along its border; when the
  long-press time is reached the count is reset to the configured value
  (default 0) at that moment, without adding and without waiting for the
  release, with a brief green flash. Keeping it held does not reset again.
  Optional sound on reset, per counter (none by default, or one of the Windows
  system sounds), with a «Test» button. It types no text. The configuration
  and the count persist between sessions.
- Media commands in the text: `{MediaPlayPause}`, `{MediaPrev}`,
  `{MediaNext}`, `{MediaStop}`, `{VolumeUp}`, `{VolumeDown}` and
  `{VolumeMute}` press that key, so a panel button can be a Play/Pause
  button; the «Media» menu inserts them at the cursor.
- Media keys: Play/Pause, previous track and next track can be assigned to
  macros and counters, from the «Media» menu next to the key field (pressing
  them to record would also control the music player). Conflicts with other
  macros and with the global keys are reported as for any key. When macros
  are suspended or outside the scope, these keys keep their normal behaviour.
- Assigning a key over a button: with the pointer over a button in the editing
  area and the focus outside edit fields, pressing a key assigns it (the button
  shows that it is waiting). Delete, Backspace, Tab, Ctrl+C and Ctrl+V keep
  their functions, as do Ctrl+Z and Ctrl+Y. If the key is already used by an
  active macro, or matches a global key (suspend, panel), nothing changes and a
  message identifies the conflict, with «Don't show again» (can be turned back
  on in Preferences).
- Multiple selection (Ctrl+click, Shift+click) to archive, restore, delete and
  copy/paste.
- Outside edit fields: Delete/Backspace deletes (with confirmation and a
  «Don't ask again» option; several macros always ask for confirmation with
  the count), Ctrl+C copies, Ctrl+V pastes. Pasting with an archived macro
  selected creates the copy in the Archive, right after it. Ctrl+Z undoes the
  last deletion: the macros come back in the same area and position, with the
  same settings and key (a key that has since come into use is removed, with a
  message); Ctrl+Y (or Ctrl+Shift+Z) deletes them again. The history is per set
  and kept while the window is open. Inside text fields, normal behaviour
  (Ctrl+Z undoes the text).
- Preference «Don't ask for confirmation before deleting macros»: when ticked,
  deletes without asking; applied and saved as soon as it changes.
- Preference «Start automatically with Windows»: actually enables or disables
  startup (including the Windows startup approval) and clearly says so if the
  change cannot be applied.
- Archive: an «Archive» divider with the archived macros and a search (title,
  text, key); archive with a button or by dragging into that area; archived
  macros are out of the keys and the panel; restoring with the key in use asks
  for confirmation and swaps the two (cancel changes nothing).
- Day (black title bar), Night and Automatic (follows Windows; the default)
  themes, applied to every window.
- Portuguese and English for the whole interface, messages, menus and
  confirmations; macro titles and contents are never translated.

### Panel

- Configurable key to show/hide the panel (Shift+F12 by default), shown on the
  panel itself.
- Grid with the title and key of the active macros; run with the mouse without
  stealing the focus from the target application; always on top by default;
  adjustable transparency (also with the mouse wheel over the panel, 5 % steps,
  with a brief indication); respects suspend, scope and execution rules.
- Rows: besides the columns, a number of rows can be set («All» by default,
  no limit). With more cells than rows × columns, the panel shows one page at
  a time, with ◀ 1 / 2 ▶ arrows below the grid that do not take the focus; all
  pages have the same size. With fewer cells, the panel only takes the rows it
  needs. Empty spaces count as cells. Keys work for macros on every page.
- Customisable look while keeping the grid: columns, rows, size, spacing,
  rounding, border, text size, colours, visible elements, title and key
  position (top, centre or bottom, independently and without unreadable
  overlap), preset styles and «Restore default». Buttons have no icon.
- Centred preview in the preferences, identical to the real panel (including
  the title bar in the theme colours) and updated on every change.

### TOML files and reloading

- `config.toml` and `conjuntos/<id>.toml` in `%APPDATA%\VirtualMacroTextInputer\`
  (copied from `%APPDATA%\Macropad\` on the first start under the new name),
  readable, with `versao_esquema`; new fields are optional (old files remain
  valid).
- Automatic reload on save, including editors that replace the file; events
  coalesced; validation before applying; an invalid file keeps the last valid
  configuration and shows file, line and column.
- Atomic writes from the interface, with no loops with the watcher; changes
  apply to future executions; a reload never reactivates macros.

## Architecture and data flow

- `src/macropad/core/`: pure Python (commands, keys, model, TOML, files,
  watcher, engine, macro operations). No Qt or Win32.
- `src/macropad/platform/`: operating-system layer (Windows: `WH_KEYBOARD_LL`
  hook, `SendInput`, clipboard, `WS_EX_NOACTIVATE`, DWM, `Run` registry key,
  mutex). `dummy.py` for tests and development.
- `src/macropad/ui/`: PySide6 (icon, settings, panel, themes).
- `src/macropad/i18n.py` + `locales/*.toml`: translations, also used by the core.
- `src/macropad/branding.py`: the visible program name.
- Threads: keyboard hook → `Engine.handle_key` (fast, non-blocking); execution
  in its own thread; the UI receives events through Qt signals.

## Security and privacy

- No network. Macro texts stay in the user's local files.
- «Paste» mode replaces the clipboard without preserving its previous content
  (accepted).

## Performance and compatibility

- Windows 10 (build 19041+) and Windows 11, Python 3.11+.
- The hook callback must answer well below LowLevelHooksTimeout (~1 s).
- Documented limitation: no interception of, or sending to, applications run as
  administrator, unless the program is too.

## Constraints

- First version with text actions only (no launching programs or scripts).
- TOML field names in Portuguese; they do not change without a new
  `versao_esquema`.
- Nothing operating-system specific in `core/`.
- Documentation: English at the repository root and in `docs/`; Portuguese
  translations kept in `docs/pt/`, updated together.

## Non-goals

- Linux version (the architecture allows it, but it is not part of this
  destination).
- Other action categories (programs, scripts, system shortcuts).
- Syntax to type `{Enter}`/`{Tab}` literally.
- Preserving the previous clipboard content.
- Installer (the package is a folder with `VirtualMacroTextInputer.exe`).
- Custom icons on the buttons (removed for now).
- Rewrite in another language (e.g. Rust); see ROADMAP.

## Acceptance criteria

- With macros active, pressing 1 sends `3E03305` without inserting the
  original 1.
- With macros suspended, pressing 1 types 1 normally.
- Outside the configured scope, the key keeps its normal behaviour.
- The suspend hotkey interrupts a sequence even during a `{Delay}`.
- Saving a valid TOML updates the configuration automatically; an invalid TOML
  does not replace the valid configuration.
- Clicking the panel sends the macro to the target application without
  stealing the focus.
- The interface behaviours above (archive, multiple selection, shortcuts,
  themes, languages, customisable panel) work as described.
- Automated validation: `pytest` with no failures.
- Manual validation: every step of `docs/MANUAL-CHECKLIST.md` ticked on real
  Windows.
- Independent review completed, with P0/P1 problems fixed or accepted by a
  recorded decision.
- `build.ps1` produces `dist\VirtualMacroTextInputer\VirtualMacroTextInputer.exe`,
  which starts and meets the criteria above.
- The repository is published to the two agreed remotes.
